1 Overview

The INE–IGM community crosswalk maps 11-digit INE community codes (Codigo) to geographic points in the IGM localizacion_poblaciones_2016 dataset (identified by id_unico). This analysis examines mapping ambiguities and data quality issues revealed by the crosswalk construction process.

Key metrics: - Total INE communities: {{nrow(distinct(crosswalk_geo_ine, Codigo))}} - Unique IGM points involved in crosswalk: {{n_distinct(crosswalk_geo_ine$id_unico)}} - Total crosswalk rows (many-to-many): {{nrow(crosswalk_geo_ine)}} - Duplicate mappings (id_unico with n>1): {{nrow(crosswalk_geo_ine |> count(id_unico) |> filter(n > 1))}}

3 Duplicate Mappings Analysis

When a single id_unico maps to multiple INE Codigo entries, it indicates either: 1. Intentional many-to-one mapping (canon splits, dispersed settlements) 2. Unintentional convergence through ambiguity resolution heuristics

3.1 Duplicate Counts by Match Status

Show code 
duplicates <- crosswalk_geo_ine |>
  count(id_unico) |>
  filter(n > 1)

dup_by_status <- crosswalk_geo_ine |>
  semi_join(duplicates, by = "id_unico") |>
  group_by(match_status) |>
  summarise(
    n_rows = n(),
    n_unique_ids = n_distinct(id_unico),
    n_unique_codigos = n_distinct(Codigo),

    .groups = "drop"

  arrange(desc(n_rows))

3.2 Breakdown

Intentional duplicates (3,168 rows / 76%):

  • Dispersed settlements (2,254 rows): 939 IGM points representing the same dispersed community. The IGM dataset intentionally recorded multiple points for dispersed settlements.
  • Canton splits (914 rows): 436 IGM points shared by 421 different INE codes because the same community was renumbered during canton boundary reorganization.

Unintended duplicates (767 rows / 18%):

  • Spatial resolution (401 rows): Ambiguous names where multiple Codigos converged on the same point after GADM municipality boundary filtering.
  • Name proximity (258 rows): Ambiguous names where multiple Codigos converged on the same point by selecting the closest to municipality centroid.
  • USCA polygon (108 rows): Multiple Codigos resolved via USCA community boundary spatial join.

Edge cases (40 rows / 1%)**:

  • Ambiguous (unresolved) (28 rows): Still-ambiguous after all spatial steps.
  • Other (12 rows): Rare cases.

4 Same Name, Same ID Convergence

How many cases have different Codigos with identical com_name mapping to the same id_unico?

same_name_same_id <- crosswalk_geo_ine |>
  group_by(id_unico, com_name) |>
  summarise(
    n_codigos = n_distinct(Codigo),
    .groups = "drop"
  ) |>
  filter(n_codigos > 1)

convergence_by_status <- crosswalk_geo_ine |>
  group_by(id_unico, com_name, match_status) |>
  summarise(
    n_codigos = n_distinct(Codigo),
    .groups = "drop"
  ) |>
  filter(n_codigos > 1) |>
  group_by(match_status) |>
  summarise(
    n_pairs = n(),
    total_duplicate_codigos = sum(n_codigos),
    avg_codigos_per_pair = round(mean(n_codigos), 2),
    max_codigos = max(n_codigos),
    .groups = "drop"
  ) |>
  arrange(desc(n_pairs))

  geom_text(aes(label = n_pairs), hjust = -0.1, size = 3) +
  scale_x_continuous(expand = expansion(mult = c(0, 0.15))) +
  labs(
    title = "Convergence Pairs by Method",
    subtitle = "Cases where different Codigos with same com_name → same id_unico",

7 Summary and Recommendations

7.1 Data Quality Findings

  1. 78% of convergences are intentional (canton splits, dispersed settlements) and well-documented by match_status labeling.

  2. 22% involve unintended convergence through disambiguation heuristics:

    • 127 cases: Same-municipality duplicates resolved by proximity (medium risk)
    • 48 cases: Cross-municipality duplicates where one point represents multiple communities (high risk)

  3. Geographic generics: Common place names (VILUYO, PAMPA GRANDE, SAN ANTONIO) appear repeatedly across municipalities. Whether these are:

    • Genuinely distinct locations poorly covered by IGM
    • The same community recorded multiple times in INE
    • Locally common names used independently in different municipalities

    …cannot be determined automatically.

7.2 For Downstream Use

  • For census/analysis work: Use the full crosswalk; match_status indicates confidence level
  • For precise geocoding: Filter to match_status %in% c("unique", "unique_via_spatial", "unique_via_usca") and manually verify unique_via_name and unique_via_spatial cross-municipality cases
  • For geographic-dispersed communities: Treat ambiguous_dispersed and ambiguous_canton_split as coordinate pools, not single points

7.3 Suggested Verification Steps

  1. Spot-check high-priority cases (VILUYO, PAMPA GRANDE, etc.) against local administrative maps
  2. Cross-reference INE canton-split documentation for expected duplications
  3. For census analysis, confirm match_status distribution hasn’t changed in latest INE release
